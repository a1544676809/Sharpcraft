# Input/Output —— 输入输出系统

把平台输入收敛成与平台无关的动作状态，把客户端状态输出到窗口与日志。名字里的"输出"指**客户端向外的反馈通道**，
不是渲染管线本身（渲染见 `docs/modules/render.md`）。

## 1. 职责范围

负责：

- **输入**：键盘按下/松开、鼠标移动与按键、滚轮、窗口焦点与鼠标捕获；映射为动作（前进/后退/跳跃/冲刺/释放鼠标）。
- **输出（本阶段）**：帧节奏（固定 tick + 可变渲染）、窗口标题诊断、日志出口；**预留**音频与 HUD 的接口位。
- 焦点丢失/捕获丢失时清空按键状态，避免"切出去再回来一直往前跑"。

明确不负责：输入绑定持久化、手柄/触屏/IME、音频混音实现、聊天与文本输入、渲染管线本身。

## 2. 输出范围的口径（需所有者确认）

"输出"在本阶段按以下三条落地，音频与 HUD 只留接口：

| 通道 | 本阶段 | 说明 |
| --- | --- | --- |
| 帧节奏 | 实现 | 固定 tick（20 Hz）+ 每帧插值渲染，时间由 `TimeProvider` 提供以便测试 |
| 窗口诊断 | 实现 | 标题显示 FPS / 坐标 / 区块数，便于手动验收 |
| 日志 | 实现 | 结构化日志出口，令牌等敏感字段禁止落盘（原则 7） |
| 音频 | **接口位** | 只定义 `IAudioOutput`，不实现混音；M6 之后再做 |
| HUD | **接口位** | 只定义 `IOverlayLayer`，实际绘制留给 UI 任务 |

若所有者要的是别的口径（例如把音频纳入本阶段），需要在此表改写后再生效。

## 3. 侧别归属

- 归属：引擎层采集（`Framework.Platform`）+ 客户端消费（`Client`）。
- 判定依据：输入是平台能力，必须经 `Framework.Platform` 抽象（原则 6）；动作语义属于客户端表现层。

## 4. 数据结构

| 类型 | 说明 | 线程 |
| --- | --- | --- |
| `KeyBindings` | 动作 → 物理键集合；默认 WASD / Space / ShiftLeft / Escape | 不可变 |
| `InputState` | 当前按下的动作集合 + 鼠标累计位移 + 滚轮 | 渲染线程 |
| `FrameInput` | 一帧只读快照：移动向量、跳跃/潜行/冲刺、视角增量 | 每帧一个结构体，零分配 |

- `FrameInput` 是 `readonly record struct`；实体层只消费 `MoveIntent`，不认识按键。


### 4.1 默认键位（对齐原版）

| 动作 | 默认键 | 原版对应 |
| --- | --- | --- |
| 前进 / 左 / 后 / 右 | W / A / S / D | 相同 |
| 跳跃 / 潜行 / 冲刺 | Space / LeftShift / LeftControl | 相同 |
| 玩家列表（按住）| Tab | 相同 |
| 打开聊天 | T | 相同 |
| 发送消息 | Enter | 相同 |
| 关闭当前界面 / 释放鼠标 | Escape | 相同 |

可重绑定 UI 仍为**有意偏离**（见 8），因此这张表是编译期常量，不持久化、不写配置文件。

## 5. 语义约定

- 移动向量 `(forward, strafe)` ∈ [−1,1]，对角归一到单位圆（与原版一致）。
- 视角：像素位移 × 灵敏度（默认 0.15°/px）；俯仰夹 −90°..+90°，偏航取模。
- 朝向 0 指向 −Z；`yaw` 以弧度进入实体层。


### 5.1 边沿语义（2026-10-29，所有者批准"先做骨架"）

只有"是否按住"不足以表达原版的按键用法：玩家列表是**按住**（Tab 按住才显示），打开聊天是**按下瞬间**。
因此每帧维护 `当前按下集合` 与 `上一帧快照`，提供三问：

| 查询 | 含义 | 用在哪 |
| --- | --- | --- |
| `IsKeyDown` | 当前按住 | 移动、冲刺、玩家列表 |
| `JustPressed` | 本帧刚按下 | 打开聊天、发送、切换界面 |
| `JustReleased` | 本帧刚松开 | 结束按住类操作 |

快照在**每帧处理事件之前**复制一次（`BeginFrame`），这样"上一帧"始终是应用真正读过的那一帧；
在帧中间交换会让同一帧的边沿被读到两次或读不到。焦点丢失时两侧集合一起清空，避免切出去再回来出现幽灵按下。

### 5.2 输入模式

| 模式 | 行为 |
| --- | --- |
| `Game` | 按键映射为动作；可打印字符丢弃 |
| `Text` | 可打印字符进入文本缓冲；**移动动作不累积**；Escape 关闭当前界面，Enter 提交 |

原版按"当前屏幕"决定按键含义，不是散落的 if；模式就是这条规则的最小载体。字符由平台层的字符回调
（`SetCharCallback`）产生，与物理键解耦——这样键盘布局、输入法产生的字符都能进缓冲区，而不是靠键码反推字符。

## 6. 帧节奏

- **固定 tick 20 Hz**（50 ms），累积时间超过一个 tick 就推进一次实体与方块更新；每帧渲染做位置插值。
- 单帧最多补 5 个 tick，避免卡顿后的"死亡螺旋"。
- 时间来源可注入，测试用假时钟推进，不 sleep。

## 7. 焦点与捕获

| 事件 | 处理 |
| --- | --- |
| 启动时 | **只有窗口已有焦点才捕获**；无焦点时保持普通光标，不占用指针 |
| 焦点丢失 | 清空按键状态、**释放鼠标捕获**（否则指针会被困在没人用的窗口里）|
| Esc | 释放捕获，并把光标交还系统 |
| 捕获已释放时点击窗口 | **重新捕获**（与原版一致：重捕获靠点击，不是再按一次 Esc）|
| 最小化 | 视为焦点丢失 |

**位置增量只在捕获状态下累积**：释放后鼠标在桌面上移动不得再转动视角；但同时仍记录光标位置，
使重新捕获后的第一个增量相对当前位置，而不是一次跨越全屏的跳变（`Repro_008_CursorCaptureTests` 守护）。

### 7.0 小键盘不作为方向键（2026-10-30 更正）

早先给方向键加了**小键盘别名**（`Keypad4/6/7/1`），理由是屏幕键盘的箭头被 GLFW 报成小键盘键。
但实测**原版自己也不把小键盘当方向键**（NumLock 关闭时原版同样不响应），所以别名是**偏离原版**的行为，已移除。
方向键只认 `Left/Right/Home/End/Delete` 本体。

未解决的问题：手机远程/屏幕键盘的箭头在**两边都不可用**，属环境限制（见 7.1 的通道说明）。

### 7.1 远程桌面与屏幕键盘（2026-10-30 实测）

两条通道要分开看：

| 通道 | 本机屏幕键盘 | 远程控制 |
| --- | --- | --- |
| **字符**（`char` 回调，用于打字）| 正常 | **正常**（官方与本客户端都能打字）|
| **按键**（`key` 回调，用于 WASD、打开聊天等）| 正常 | **不产生**（官方同样无响应）|

即远程工具注入的是**文本**而不是**按键**序列。所以"打开聊天框"在远程下按不出来（与原版一致），
但框一旦打开，远程打字是正常的。这不是实现缺陷，属**环境限制**，且与原版行为一致。

排障手段：`MC_INPUT_TRACE=1` 会把每个 `key`/`char` 事件打到标准输出（含 keycode、scancode、action、mods），
一眼能分清"事件没到"还是"到了没处理"。

## 8. 与原版对齐与偏离

对齐：WASD 正交移动、Space 跳跃、Shift 潜行、鼠标相对位移控制视角、Esc 释放鼠标、20 Hz 逻辑 tick。

偏离（有意）：不做可重绑定 UI、不做手柄、不做按键回放。
