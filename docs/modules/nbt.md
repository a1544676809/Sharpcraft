# NBT 模块（Common/Nbt）

网络与数据包里的 NBT 读写：标签类型表、复合/列表、数组、字符串，以及**读取上限**。

## 1. 职责范围

负责：

- 解析网络格式 NBT（**根标签无名字**）与带名字的存储格式。
- 写出同样的格式（用于测试夹具与后续发包）。
- 类型化访问器与插入顺序保留。
- 深度/长度上限，防止恶意数据触发巨量分配。

不负责：

- 组件（Component）语义解析——NBT 只是容器，语义在上层。
- 数据修复（DataFixer）与版本迁移。
- 区域文件（`.mca`）读写——那属于资产/存档管线，另行设计。

## 2. 侧别归属

`Common`：两侧都可能解析 NBT（服务端权威逻辑、客户端数据包）。

## 3. 关键设计

### 3.1 类型与编码

| id | 类型 | 编码 |
| --- | --- | --- |
| 1–6 | Byte/Short/Int/Long/Float/Double | 大端定长 |
| 7 | ByteArray | int32 长度 + 字节 |
| 8 | String | **uint16 字节长度**（不是 VarInt）+ UTF-8 |
| 9 | List | 元素类型 id + int32 数量 + 元素 |
| 10 | Compound | 循环 `(类型, 名字, 载荷)` 直到类型 0 |
| 11/12 | IntArray/LongArray | int32 数量 + 定长大端元素 |

注意字符串长度是 **uint16**，与协议其余部分的 VarInt 不同；写错会让解析器整体错位。

### 3.2 两种根

- 网络：`主类型(10) + 复合体`，**没有名字**（1.20.2 起）。
- 存储：`主类型(10) + 名字 + 复合体`。

二者不可混用；`ReadNetworkRoot` 与 `ReadNamedRoot` 分开提供，避免"读的时候多吞两个字节"。

### 3.3 上限（读取时强制）

| 项 | 值 | 理由 |
| --- | --- | --- |
| 嵌套深度 | 512 | 与原版一致；防止栈溢出 |
| 列表元素数 | 2^24 | 先校验后分配 |
| 数组字节数 | 2^27 | 同上 |
| 字符串长度 | uint16 天然上限 | — |

### 3.4 语义细节

- 复合体**保留插入顺序**（写回与服务端比对时需要）。
- 列表是**同构**的；`End` 类型只允许空列表，非空即错误。
- 类型化访问器在类型不符时返回默认值而不是抛异常（NBT 常用于可选字段）。

## 4. 测试要求

- 全类型往返、数组往返、嵌套复合/列表、空复合/空列表、带名字根。
- 截断、非复合根、未知类型 id、超大列表长度、超深嵌套、非空 End 列表，均必须被拒绝。
- 类型化访问器的回退行为。
