# 客户端世界模块（World）

客户端的**世界数据**表示：区块存储、方块状态查询、维度与本地玩家标识。**不含渲染**（渲染另立模块，原则 11 排在其后）。

## 1. 职责范围

负责：

- 方块状态的高效存储（调色板容器 + 打包 long 布局）。
- 区块段 / 区块列的组织，含负数坐标与垂直分段边界。
- 世界坐标 → 区块 → 段 → 方块状态的查询路径。
- 本地玩家 entity id、视距、维度列表（来自 JoinGame）。

不负责：

- 区块包解析（下一步，见 `docs/specs/network/`）。
- 光照、实体、粒子、声音。
- 渲染、网格构建、GPU 资源。
- 世界模拟（属于服务端侧，原则 5）。

## 2. 侧别归属

| 类型 | 程序集 | 理由 |
| --- | --- | --- |
| `PalettedContainer` / `ChunkSection` / `LevelChunk` | `Common` | 纯数据结构，两侧都可能需要（服务端权威逻辑同样用得到） |
| `ClientWorld` | `Client` | 客户端视角的聚合与查询，依赖 `Common` 的容器 |

`Common` MUST NOT 引用 `Client`（架构测试已强制）。

## 3. 关键设计

### 3.1 调色板容器

- 三种策略：**单值**（bits=0）、**本地调色板**（bits 2..8）、**直接**（bits 15，读取用）。
- 打包规则：每 64 位整数放 `64 / bits` 个条目，**条目不得跨 long 边界**（与原版一致）。
- 调色板索引按首次出现顺序分配；**只在当前位宽放不下时才加宽**（这一点踩过坑：每次新值都加宽会瞬间耗尽位宽）。
- 线性索引顺序：`(y << 8) | (z << 4) | x`。

### 3.2 分段与列

- 段 = 16³ = 4096 个方块状态。
- 区块列持有 `minSectionY .. minSectionY + count - 1`；主世界 1.18+ 为 `-4..19`（24 段）。
- 缺失段返回回退值而不是抛异常：区块可能尚未收到。
- 非空气计数用于快速判空（服务端也会给出该值，解析时以其为准）。

### 3.3 坐标

- 世界坐标 → 区块用**算术右移**，区块内相对坐标用 `& 15`，禁止用 `/` 与 `%`（负数会错）。
- 已由 `docs/analysis/common/coordinates.md` 与其实测向量约束。

## 4. 测试要求

- 调色板：单值、加宽、首次出现顺序、跨 long 边界、解析路径、异常输入。
- 段/列：索引顺序、非空气计数、垂直边界、未加载段回退。
- 世界：负数坐标、未加载区块回退、重复添加、移除、坐标打包往返（含 `int.MinValue`）。
