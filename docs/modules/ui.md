# UI —— 界面层

把界面拆成**声明式的结构与外观**（文件，可热加载）与**代码化的行为**（程序集，可热重载）两半，
并在单一 2D 批次里绘制，做到"改一个像素不用重新编译，改一段逻辑不用重启"。

## 1. 职责范围

负责：

- 屏幕栈与生命周期（打开 / 渲染 / 每刻更新 / 关闭 / 暂停世界输入）
- 控件树（容器、标签、按钮、输入框、列表、物品槽）与布局
- 声明式界面的解析、校验、版本兼容与热加载交换
- 界面绘制：正交投影、纹理与形状批次、裁剪栈、位图字体排版
- 输入路由：命中测试、焦点、捕获（拖拽）、键盘导航
- 与游戏逻辑的**只读**接线（血量、物品栏、聊天记录、玩家列表）

明确不负责：

- 世界渲染与区块网格（`docs/modules/render.md`）
- 输入采集与动作映射（`docs/modules/input.md`）；本层只消费动作后的状态
- 游戏规则（背包容量、合成、聊天命令语义）——这些属于 `Common` 的玩法层
- 字体、控件贴图等资产本体：一律由启动器从用户本地 jar 提取（原则 3），仓库内只有加载逻辑

## 2. 侧别归属

- 归属：`Client`
- 判定依据：界面是纯客户端表现，不参与权威世界状态；服务端只传输容器内容、聊天与玩家列表等数据，
  由客户端决定如何呈现。与 `docs/architecture/boundaries.md` 的"Client 负责渲染 / 输入 / UI"一致。

## 3. 依赖关系

| 方向 | 对象 | 说明 |
| --- | --- | --- |
| 依赖 | `Framework.Rendering` 的 **2D 批次原语** | 只依赖批次与纹理句柄抽象，不接触 WGPU 类型 |
| 依赖 | `Common` 的数据结构 | 物品栈、聊天消息、玩家列表条目等只读数据 |
| 依赖 | `Client/Assets` | 图集、位图字体、控件贴图的解析结果 |
| 被依赖 | `Modding` 的界面扩展契约 | 模组注册控件与屏幕，只经公开接口 |
| 被依赖 | 启动层（`Sharpcraft.Launcher` 的 `window` 路径） | 打开屏幕、转发输入 |

依赖方向自检：不出现 `Client ↔ Server` 直引；界面层不引用启动器与资产提取器等外围宿主层；
`Framework` 不反向引用 `Client`。

## 4. 对外契约

- 接口：`IUiScreen`（生命周期）、`IUiWidget`（测量 / 布局 / 绘制数据 / 命中测试）、`IUiHost`（打开 / 关闭 / 交换）
- 数据：`UiMarkupDocument`（不可变、已校验）、`UiDrawList`（本帧绘制数据）、`UiMetrics`（性能计数器）
- 事件：屏幕开闭、控件激活、文本提交、滚动、拖拽开始 / 移动 / 放下、热加载成功 / 失败
- 明确不暴露：控件内部的 GPU 资源、解析器的中间状态、WGPU 句柄（原则 6）、其他控件的可变字段

## 5. 关键数据结构

| 结构 | 性质 | 说明 |
| --- | --- | --- |
| `UiMarkupDocument` | 不可变 | 解析 + 校验后的声明式文档；含 schema 版本 |
| `UiNode` | 不可变 | 元素 + 属性 + 子节点 + 绑定的行为处理器名 |
| `UiWidget` | 可变、池化 | 实例化后的控件；只在交换或结构变更时重建 |
| `UiLayout` | 可变、池化 | 由控件树一次算出的矩形，供命中测试与绘制共用 |
| `UiDrawList` | 每帧复用 | 四边形、文本运行、裁剪区间；**不分配** |
| `UiGlyphAtlas` | 常驻 | 位图字体按需烘焙的字形；命中率可观测 |
| `UiMetrics` | 常驻 | 布局次数、提交次数、四边形数、分配字节、解析耗时 |

## 6. 每帧运行流程

```
文件变化（可选） → 后台解析 + 校验 → 原子交换（迁移状态）
        ↓
输入路由（命中测试 → 焦点 → 捕获）           ← 每帧
        ↓
布局（仅脏时执行，单趟）                       ← 空闲帧 0 次
        ↓
构建绘制列表（控件只追加数据，不发绘制调用）    ← 每帧，池化
        ↓
排序 + 合批（layer → 材质 → 裁剪）→ ≤3 次提交  ← 每帧
```

约束：

- **控件不发绘制调用**：这是性能上限与可维护性的共同前提，避免每个控件各自切换管线状态。
- **布局只在脏时执行**：控件树结构、尺寸、文本内容变化才置脏；空闲帧必须为零次。
- **文本排版缓存**：按（字符串、样式、可用宽度）缓存行布局，内容不变不重算。

## 7. 声明式格式（最小内核）

自研的类 XAML 格式，**不是** WPF XAML（跨平台不可用，原则 6）。刻意保持极小，按需扩展。

```xml
<screen id="chat" version="1">
  <import src="ui/style/default.xml"/>
  <stack anchor="bottom" direction="vertical" margin="8">
    <list id="messages" grow="1" item-template="chat-line"/>
    <textbox id="input" hint="chat.hint" submit="SendChat"/>
  </stack>
</screen>
```

- 元素集合最小化：`screen / import / stack / grid / panel / label / button / textbox / list / item / texture`
- 属性只描述**结构与外观**（锚点、方向、间距、尺寸约束、样式引用、本地化键）
- `submit="SendChat"` 之类是**具名行为处理器**，实现留在代码里，二者通过名字绑定
- 文案一律走本地化键，元素与属性名用英文（与其他代码标识符一致）
- 布局数值**来源于原版的可观测布局**，因此像素级对照依然成立

校验与兼容：

- 文档必须带 `version`；未知元素或未知属性 = **可定位的报错**，不静默忽略
- 解析失败**原子回退**到上一份可用文档，屏幕不消失，错误进入诊断通道
- 解析在后台线程完成；**渲染线程不解析任何文件**

## 8. 热加载边界

| 变化内容 | 机制 | 是否重启进程 |
| --- | --- | --- |
| 布局、间距、样式、贴图引用、文案键 | 文件监听 → 后台解析 → 帧边界原子交换 | 否 |
| 行为（处理器、数据绑定逻辑） | 程序集热重载（原则 2 的 collectible ALC） | 否 |
| 控件类型本身 | 同上（控件属于行为侧） | 否 |

交换语义：

- 交换发生在**帧边界**，本帧要么全旧要么全新，不出现半更新状态
- 交换时按控件 `id` 迁移滚动位置、输入框内容、焦点与捕获状态
- 结构不可迁移时（例如控件被删除）允许丢弃该控件的状态，但**不得**让屏幕整体失效

## 9. 2D 渲染契约

- 独立于世界渲染的管线：正交投影、关闭深度测试、开启 alpha 混合、`scissor` 裁剪
- 顶点格式专用且紧凑（位置 2 + UV 2 + 颜色 4，约 20 字节），**不复用** 3D 的 48 字节布局
- 坐标以**虚拟分辨率**表达，按 GUI 缩放映射到像素；缩放采用浮点并对齐到像素网格，避免整数取整错位
- 形状（纯色矩形、边框）与纹理、文字共用同一批次，按材质分段提交
- 顶点与索引缓冲常驻并按需增长（沿用世界几何所用的"常驻 + 原地改写"策略，见 `docs/specs/network/play-movement.md` §7.25）

## 10. 性能预算与测量

数值写入 `docs/specs/quality-attributes.md` 并纳入门禁；此处只列指标与判定口径。

| 指标 | 阈值 | 测量方法 |
| --- | --- | --- |
| UI 每帧 CPU（聊天 + 玩家列表） | ≤ 0.3 ms | 窗口日志 `ui:` 分段计时 |
| UI 每帧 CPU（36 槽容器） | ≤ 1.0 ms | 同上 |
| 稳态分配 | **0 字节 / 帧** | `GC.GetAllocatedBytesForCurrentThread` 前后差（原则 3.6） |
| 绘制提交次数 | ≤ 3 次 / 屏幕 | `UiMetrics` |
| 四边形数（20 人玩家列表） | ≤ 200 | `UiMetrics` |
| 布局重算 | 空闲帧 **0** 次、每帧 ≤ 1 次 | 计数器 |
| 字形缓存命中率 | ≥ 99% | 计数器 |
| 热加载 | 渲染线程解析次数 **= 0** | 线程断言 + 耗时统计 |
| 常驻内存（树 + 字形图集） | ≤ 8 MB | 运行后报告 |

失败判定：任一阈值被超出即视为回归，需在提交内修复或记录受控偏差（原则 9）。

## 11. 防扩散规则

1. **YAGNI 门禁**：新增控件类型必须已有真实屏幕在使用，否则不予合并
2. **单一绘制出口**：只有 batcher 接触批次；控件只追加数据
3. **布局单趟**：不引入通用约束求解器；三种容器不够时，改用**纯代码屏幕**而不是扩引擎
4. **纯代码逃生舱**：任何屏幕允许完全用代码实现（容器 / 合成先走这条），声明式只覆盖稳定的部分
5. **架构门禁进 CI**：`Client.Ui` 不得引用 WGPU 类型或启动器；`Framework` 不得引用控件；模组契约不得引用内部类型
6. **热路径标注**：所有每帧路径标 `[HotPath]` 并配零分配测试

## 12. 测试策略

| 层 | 测试 |
| --- | --- |
| 解析与校验 | 合法/非法文档、未知元素、缺 `version`、回退路径 |
| 布局 | 数值金样（锚点、间距、增长、裁剪），以矩形断言而非截图 |
| 绘制数据 | 四边形与文本运行的顺序、裁剪分段、合批分组 |
| 输入路由 | 命中优先级、焦点转移、捕获期间的事件吞掉 |
| 性能 | 每帧分配断言、提交次数、布局计数、字形命中率 |
| 热加载 | 交换后状态迁移、解析失败回退、渲染线程零解析 |
| 架构 | 依赖方向门禁（与现有 `Architecture.Tests` 同风格） |

## 13. 分期与出口条件

| 阶段 | 内容 | 出口证据 |
| --- | --- | --- |
| P0 内核 | 2D 批次 + 位图字体 + 裁剪 + 最小声明式（3 元素）+ 热加载 | 屏幕热改文件即时生效；0 分配；提交 ≤ 3 |
| P1（M5 出口） | 聊天浮层 + 玩家列表 | 真实服务器收到并显示聊天；列表与在线一致；预算达标 |
| P2 | 控件扩展（grid / list / button / textbox / 滚动） | 设置屏幕可用，预算不退化 |
| P3 | 容器与背包（含拖拽语义等效） | 与官方客户端逐项对照 |

## 14. 风险与未决项

| 风险 | 缓解 |
| --- | --- |
| 布局引擎越写越大 | 固定单趟 + 仅三种容器；不足即改纯代码屏幕 |
| 文本测量每帧重算 | 行布局缓存 + 脏标记 |
| CJK 宽度与断行 | 位图字体宽度表；先单行截断，换行后续补 |
| 热加载丢状态 | 按 `id` 迁移；不可迁移时只丢该控件 |
| 声明式表达力不足 | 纯代码逃生舱，不硬撑扩展格式 |
| 与原版像素级偏差 | 布局数值取自原版可观测布局，用矩形断言守护 |

未决项：

- 声明式格式的具体语法（XML 还是紧凑 JSON）待 P0 原型后定稿
- 键盘导航与手柄支持的优先级待定
- 是否引入可滚动的富文本（聊天分行、颜色、点击事件）细节待 P1
- 与模组契约的具体形状（注册控件 vs 注册整屏）待 `docs/modules/modding.md` 对齐
