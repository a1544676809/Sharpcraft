# 帧时间基线（T-833 收口）

> 用途：后续任何渲染性能改动，都以此文件为对照。数字变了先改这里，再改代码。

## 1. 测量条件

| 项 | 值 |
| --- | --- |
| 构建 | `-c Release`（Debug 关闭优化会让结果虚高 1.4–3.3 倍） |
| 呈现模式 | `MC_PRESENT_MODE=immediate` |
| 分辨率 / 视距 | 1400×754 / 12 |
| 时间 | `MC_FORCE_DAYTIME=1` |
| 采样 | `MC_FRAME_CPU=1`，取 `frame-cpu` 行，60 帧窗口 |
| 机位 | 地表 `-74.7 121 37.3` yaw 178.4 pitch 10；地下 `-73.3 30 164.7` |
| 电源 | 必须同电源状态；电池与市电不可交叉比较 |

**跨运行比较不可靠**：同一场景不同运行可差 10%+，实测中 `prep-entities` 曾在两次相邻运行间从 0.068 跳到 0.287 ms。**只有同进程 A/B（`MC_AB_TOGGLE`）或同一次运行内的阶段占比可信。**

## 2. 阶段拆分（地表，整帧约 1.79–2.15 ms）

| 阶段 | 耗时 (ms) | 占比 | 归因 |
| --- | --- | --- | --- |
| `sub-finish` | 0.38–0.48 | **24%** | `CommandEncoder.Finish()`，纯 CPU 命令封包与跨 pass 纹理屏障合成 |
| `swap` | 0.32–0.35 | 20% | `surface.Present()` |
| `sub-queue` | 0.15–0.18 | 10% | `Queue.Submit` |
| `oit` | 0.14–0.19 | 9% | 参考 OIT 五阶段 |
| `scene-terrain` | 0.14–0.22 | 9% | 地形/切图/半透明录制 |
| `prep-entities` | 0.07–0.29 | 4–13% | 波动最大，含实体收集 |
| `prep-pump` | 0.04 | 2% | 窗口消息泵（`frame-gap` 另计 0.00–0.002，即无呈现等待） |
| 其余 | ≈0.44 | 20% | 天空/云/UI/相机等 |

## 3. 已经证伪的归因（勿重复调查）

| 曾经的判断 | 实测结论 |
| --- | --- |
| 「`prep-pump` 0.92 ms 是呈现等待」 | **错**。拆分后 `frame-gap=0.002`、消息泵 `0.048`。旧数字来自不同构建与机位 |
| 「`Finish()` 可能是 GPU 同步」 | **错**。wgpu 的 `finish()` 是纯 CPU；GPU 同步只发生在 `GetCurrentTexture` / `Submit` / `Present` |
| 「wgpu 校验层在 `Finish()` 里吃掉 0.3–0.4 ms」 | **错**。`Instance.Create()` 的 IL 是 `initobj` 全零描述符，即 `InstanceFlags.None`，校验本就关闭 |
| 「按可见性切段增加了命令数量」 | **基本不成立**。遮挡开启后 `sub-finish` 仅多 0.054 ms |

## 4. 遮挡剔除的位置

遮挡剔除把三角形从 **1,157,844 削到 257,366（−78%）**，但帧时间几乎不变（同会话 A/B：1.83 → 1.76 ms）。

原因是瓶颈不在 GPU 绘制量，而在 CPU 的 `Finish()` + `Present()` + 命令录制。**不要再把"减少三角形"当作提速手段**，除非先改帧结构。

## 5. 每个 RenderPass 的实测代价（关键杠杆）

用已有的 `MC_SKIP_OIT` 开关做同机位对照，OIT 组共 **8 个 pass**：

| 指标 | OIT 开 | OIT 关 | 差值 |
| --- | --- | --- | --- |
| 整帧 | 1.637 | 1.179 | −0.458 ms |
| `sub-finish` | 0.388 | 0.203 | **−0.185 ms** |
| `oit` 阶段 | 0.158 | 0.008 | −0.150 ms |
| `swap` | 0.304 | 0.271 | −0.033 ms |

**结论：每个 pass ≈ 0.023 ms 的 `Finish()` 成本，8 个 OIT pass 占命令封包成本的 48%。**

这条把"减少 pass"从推测变成可计算：合并 2 个 pass 约省 0.046 ms，合并 4 个约省 0.09 ms。**与 draw 数无关**——这是为什么遮挡剔除砍 78% 三角形换不来帧时间。

## 6. 下一步有量级空间的方向

1. 减少 RenderPass 数量（`Finish()` 成本与 pass 数、跨 pass 纹理切换成正比，与 draw 数无关）
2. 云参考 OIT 常开——云不可见时能否跳过整组
3. 帧间流水线（当前每帧同步提交 + 呈现）
