# 可测质量属性（Quality Attributes）

AGENTS.md 原则 12：质量需求必须写成"指标 + 阈值 + 测量方法 + 失败判定"。**不可测的描述不得作为验收标准。**

阈值列写 `[待定]` 的，表示尚未定稿；一旦定稿不得留在 `[待定]`，必须给出具体数字或明确的测量协议。

## QA-1 性能

| 指标 | 阈值 | 测量方法 | 失败判定 |
| --- | --- | --- | --- |
| 帧时间 P50 / P99 | P50 ≤ 16.6 ms，P99 ≤ 33 ms（60 FPS 基线）`[待定]` | `benchmarks/` 固定场景回放，记录分布而非均值 | 连续 3 次运行超阈值 |
| tick 耗时 P99 | ≤ 50 ms/tick（20 TPS 预算）`[待定]` | 内置 profiler 采样 + 基准场景 | 任一次超预算即为回归 |
| 稳态分配（热路径） | **0 字节/帧、0 字节/刻** | `[HotPath]` + `AllocationAssert`（已实现） | 分配测试失败 |
| 内存峰值 / GC 次数 | Gen2 GC ≤ 1 次/分钟；峰值 `[待定]` | 运行时计数器采样 | 超阈值即回归 |
| 启动到首帧 | `[待定]` | 冷启动计时（含资产校验） | 超阈值 |

## QA-2 协议一致性

| 指标 | 阈值 | 测量方法 | 失败判定 |
| --- | --- | --- | --- |
| 协议版本 | 必须 = **777**（26.3） | 握手阶段断言常量 | 任何其他值即失败 |
| 数据包编解码往返 | 100% 无损 | 对每个包做 `decode(encode(x)) == x` 属性测试 | 任一包不一致 |
| 与原版服务端互通 | 能完成登录→配置→进入世界 | 集成测试连本地原版服务端（脚本化，非人工） | 任一阶段失败 |
| 注册表同步顺序 | 与服务端注册顺序逐项一致 | 对比同步包元素序列 | 顺序或数量不同 |

## QA-3 模组热加载

| 指标 | 阈值 | 测量方法 | 失败判定 |
| --- | --- | --- | --- |
| 热卸载后 ALC 可回收 | 卸载后强制 GC，`AssemblyLoadContext` 弱引用失效 | 自动化测试：弱引用 + `GC.Collect()` | 弱引用仍存活 |
| 重载后注册项正确 | 重载 N 次后注册项数量与内容不变 | 循环重载 100 次断言状态 | 数量漂移或异常 |
| 卸载期间零残留 | 宿主不持有模组类型/实例强引用 | 反射扫描 + 弱引用表 | 发现强引用 |
| 热重载不可中断世界 | 重载后世界状态哈希不变 | 状态哈希快照对比 | 哈希变化 |

## 帧尖峰归因（2026-10-29，T-115）

测量：1801 帧 / 30 s（约 60 fps），逐慢帧记录 `updates / uploaded / gc`。

| 观测 | 数值 |
| --- | --- |
| 超过 33 ms 的帧 | 6 帧（0.3%）|
| 最差帧 | 60.1 ms（第 1306 帧）；复测 90.5 / 183.9 ms，超限帧占比 0.3% → 0.9% → **1.14%**（趋近 2% 复查线）|
| 该帧上传量 | **+99 679 KiB（单条更新）** |
| 次差帧 | 52.4 ms，+27 644 KiB / 4 条更新 |
| GC 计数 | 慢帧前后无跳变，**不是 GC** |

结论：尖峰来自**单帧内无上限的区块几何上传**。所有者裁决：**接受为受控偏差**（ADR-0011），
不实现切片上传；复查条件写在 ADR 中（超限帧占比 >2%、出现连续 3 帧超限、或无地形到达时仍尖峰）。

## 使用规则

1. 新增质量需求 → 先在本文件补行（含测量方法），再谈实现。
2. 阈值变更属于规格变更，需 ADR（原则 12）。
3. 每个阈值最终都必须有自动化检查落到 `tests/` 或 `benchmarks/`；否则该行视为"未生效"。

## 区块网格构建基准（chunk-mesh）

- **指标**：区块就绪后，前 64 个区块网格建成的**平均距离**（应尽量小）、网格重建总耗时、单帧最坏耗时（`worst frame`）。
- **测量方法**：`benchmarks/chunk-mesh/run.ps1` —— 多个实例经原版客户端 RPC 传送到同一坐标（如 `-83 120 46`），
  `MC_DEV_BENCH=1` + `MC_BENCH_BUFFER=<秒>` + `MC_BENCH_DELAY=<秒>`：延迟期内正常装入（先把 bot 传送到同一点），
之后才缓存服务端区块，**达到期望区块数或超时（先到者）**一次性装入并开始计时。
传送用 `/tp @a <坐标>`（选择器，避免依赖玩家名），实测两 bot 落点均为 **(-82.5, 120.0, 46.5)**。
- **失败判定**：①未开启 `MC_DEV_BENCH` 时出现任何基准分支（发布形态被污染）②平均距离退化到 FIFO 水平（>2.5 区块）
  ③单帧最坏耗时超过既定预算（当前记录 161 ms，目标待定）。
- **门禁**：`MC_DEV_BENCH` 默认关闭；未设置时上述开关无效，且启动不打印 `benchmark mode`。
