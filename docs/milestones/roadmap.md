# 里程碑规划（Roadmap）

本文件回答"整体任务拆成哪些里程碑、每个的出口条件是什么、现在在哪"。**易变状态不写在这里**（那是 `docs/STATE.md` 的职责），这里只写稳定的阶段划分与验收标准。

## 划分原则

里程碑按**可交付能力的闭环**切分，而不是按代码分层。每个里程碑必须满足：

1. 有可执行证据（命令 + 观测到的数值/图像），不靠"看起来做了"；
2. 完成后能独立回答"现在能做什么"，且不依赖下一个里程碑；
3. 涉及原则 3、7、8 的部分优先——它们是宪章的一等约束。

## M3 —— 资产管线 + 启动器闭环（进行中）

出口条件：**用一条命令，从用户本地 jar 走到带纹理的窗口画面**。

| 序 | 任务 | 状态 |
| --- | --- | --- |
| 1 | 里程碑规划与资产清单（本文件 + `docs/analysis/assets/jar-entry-map.md`） | 完成 |
| 2 | 资产模块设计 `docs/modules/assets.md` + ADR-0005 | 已评审 |
| 3 | T-032 版本清单解析 + jar SHA-1 校验 | 完成 |
| 4 | T-033 资产打包器：白名单 → 单文件 pack（zip + manifest、原子、幂等、zip-slip 防护） | 完成 |
| 5 | T-034 资源解析层：`IAssetSource`（pack 读取器 + 官方 objects 只读挂载）+ 有序栈 + 资源包预留 | 完成 |
| 6 | T-035 启动器承接：`assets` / `launch` 子命令 | 完成 |
| 7 | T-036 多账号与离线登录闸门（原则 7.1） | 完成 |
| 8 | T-037 纹理接入渲染（图集、UV、采样器、着色器采样） | 完成（2026-10-29 官方 jar 复验） |

出口验收：

- `launcher assets --jar <path>` 完成校验与打包，产出单个 pack 并打印报告；
- `launcher window <address>` 显示带纹理的世界（截图存档）；
- 仓库内不出现任何资产，`git status` 干净；
- 测试覆盖：合成 jar 全链路、篡改场景、幂等、zip-slip、成对 `.mcmeta`、pack 读回一致；
- 音频走官方索引只读挂载，缺失时报错可诊断。

## M4 —— 实体系统根基 + 输入输出（进行中）

出口条件：**能操作，世界会变**。

> 范围修正（所有者 2026-10-29）：原版里玩家就是实体系统的一员，因此 M4 不是"给玩家写一套物理"，而是
> **打下整个实体系统的根基**，并初步建立输入输出系统；等效性在这一层同样不可或缺。

- 实体根基（`Common`）：`Aabb` / `EntityDimensions` / `Entity`（逐轴碰撞、碰撞标志、上台阶）/
  `LivingEntity`（`Travel`：方块摩擦、输入摩擦、重力、水平与竖直阻力）/ `PlayerEntity`（尺寸与属性）
- 输入输出系统（`docs/modules/input.md`）：键鼠与焦点采集、动作映射、固定 20 Hz tick + 渲染插值、
  窗口诊断与日志输出；音频与 HUD 只留接口
- 玩家移动与相机控制（相机取玩家眼位）
- `block_update` / `section_blocks_update` → 局部重网格（走池化路径）
- 出口验收：能走进一个方块、挖掉一个方块并看到地形变化

进度：

- [x] 玩家物理原型（`PlayerBody`，9 项测试）——**将迁入 `Common/Entities`**，原型里的两个顺序缺陷已留回归
- [ ] 实体根基重构：`Entity` / `LivingEntity` 与摩擦影响的速度系数（`0.21600002 / f³`）
- [ ] 输入输出系统（`WindowHost` 需先暴露键鼠与焦点事件面）
- [ ] 相机追随与鼠标视角
- [ ] 区块局部更新与重网格

## 待决项对里程碑的影响

| 待决项（AGENTS §5） | 影响 |
| --- | --- |
| 运行时形态（JIT/AOT/单文件） | 影响 M3 的分发形态与 AOT/Trim 分析器启用时机；不阻塞功能 |
| 性能目标数值 | 影响 M4 帧预算判定；建议 M4 开工前定稿 |
| 着色器包支持范围 | 决定 M6 的接入点接口形状 |
| 令牌安全存储 | M3 的启动器承接部分会触及（沿用当前仓库外缓存，生产前需换平台安全存储） |
