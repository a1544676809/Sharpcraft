# 原版等效性核查（2026-10-30，最终验证轮）

逐项把我们的实现与原版参考对照。**实现细节可以不同（更 C#、更快），结果必须等效**——本文记录每一条的依据与结论。

## 1. 玩家模型部件尺寸

依据：`ref://mc-26.3-analysis/src/net/minecraft/client/model/player/PlayerModel.java` 与 `HumanoidModel.java`（1 像素 = 1/16 方块，模型总高 32 像素）。

| 部件 | 原版 addBox | 换算 | 我方 | 结论 |
| --- | --- | --- | --- | --- |
| 头 | `(-4,-8,-4, 8,8,8)` | 0.5³ | 8×8×8 px | ✅ 一致 |
| 身体 | `(-4,0,-2, 8,12,4)` | 0.5×0.75×0.25 | 8×12×4 px | ✅ 一致 |
| 手臂 | classic `4×12×4`；slim `3×12×4` | 0.25 或 0.1875 宽 | **3×12×4（slim）** | ⚠️ 取 slim 变体，需在文档标注（原版两种皮肤模型都存在）|
| 腿 | `(-2,0,-2, 4,12,4)` | 0.25×0.75×0.25 | 4×12×4 px | ✅ 一致 |
| 姿态 | 腿 `y=12`、身 `y=0`、头 `y=0`（+y 向下）| 自脚向上：腿 0–12、身 12–24、头 24–32 px | 相同 | ✅ 一致 |

模型 32 像素按 `ModelScale = 1.8 / 2.0 = 0.9` 拟合到碰撞盒高度 1.8——与原版"模型 32px、实体 1.8 高"的做法一致。

## 2. 箱子模型

依据：`ref://mc-26.3-analysis/src/net/minecraft/client/model/object/chest/ChestModel.java`

- `bottom`：`addBox(1,0,1, 14,10,14)`，`PartPose.ZERO` ⇒ **14/16 宽、14/16 深、底部贴在方块底面 y=0**。
- `lid`：`addBox(1,0,0, 14,5,14)`，`offset(0,9,1)` ⇒ 顶盖到 14 px，整体高 **14/16**。

我方占位：14/16 立方、水平居中。**本轮修掉一处偏差**：此前整体抬高 1/16（`(1-size)/2`），与参考的"贴地"不符；
改为贴地后 `minY` 由 64.0625 → **64.0**，测试同步更正，方块实体像素证据由 329 → **311 像素**（(461,70)）——
移动量与 1/16 方块一致，说明修正生效。

## 3. 方块实体数据包编码

依据：`ClientboundLevelChunkPacketData.java` L99–131。`packedXZ` 为**单字节**（高半字节 X、低半字节 Z），`y` 为**绝对 short**，`type` VarInt，`tag` NBT。
我方解析与之一致（`BlockEntityRecord`）。

## 4. 阴影/光照、雾、天空

- 面上明暗系数（顶/底/侧）与 `MinimumBrightness` 为自研近似，**尚未与原版逐项核对**，属未完成项。
- 雾：距离 = 渲染距离（区块）×16、颜色随环境属性——已按 `FogRenderer` 的行为规格记录，未做逐环境验证。
- 天空：渐变色已采样对齐；天体（日/月/星/日出）未实现。

## 5. 结论

几何与数据编码层面（玩家部件、箱子尺寸与落位、方块实体包格式）**已与原版对齐**；
光照/雾/天空的细节仍属部分对齐，已在里程碑文档中列为未完成项。

## 真实服务器目视结果与已知缺口（2026-10-30）

接真实服务器（NeoForge）窗口实测：草地、泥土、石头、雪、树干**均能正确显示**，区块网格与位置同步正常。
画面上仍有大面积**黑色碎斑**。

**结论（由项目所有者确认）**：碎斑来自我们**尚未实现的半透明/镂空方块**与**着色器驱动的生物群系着色**：

- 树叶等镂空方块需要 `cutout` 类渲染层（不是当前的两层 opaque/translucent）；
- 草方块/树叶的**颜色由着色器按生物群系调制**，我们还没接 biome tint。

这两项属于后续开发内容，不是数据 id 错位，也不是图集渗色（我先前的猜测已排除）。
