# 离屏帧的界面 pass 与逐像素校验（T-104 / T-159）

## 1. 问题

`frame` / `frame local` 走 `OffscreenRenderer.Render`，只有地形管线一个 pass，**没有界面 pass**。
因此：

- 界面（聊天、Tab 列表、提示框、动作栏）无法通过截图验证，只能开窗口目视；
- "gamma 空间混合是否正确""ARGB 是否被写成 BGRA"这类问题无法逐像素证明。

窗口路径 `WindowedRenderer` 已有界面 pass（L564 起），离屏路径缺的是同一件事。

## 2. 行为规格

- 离屏帧的**像素结果**必须与窗口在同一帧、同一尺寸下的结果一致：先地形，再界面，同样的混合状态。
- 离屏与窗口共用**同一份界面几何**（`UiGeometry`）与**同一套坐标约定**（整数缩放后的虚拟像素）。
- 目标格式与窗口一致：`BGRA8Unorm`（`OffscreenRenderer` 已有该常量，见 L958 附近的着色器来源）。

## 3. 逐像素校验（T-159）

在离屏帧上画一个**颜色已知**的实心矩形，回读该点像素并断言精确值：

| 输入（ARGB） | 期望像素（BGRA8 读回后按 RGBA 解释） |
| --- | --- |
| `0xFF3366CC`（不透明）| R=0x33, G=0x66, B=0xCC, A=0xFF |
| `0x803366CC`（半透明，底色不透明黑）| R≈0x19, G≈0x33, B≈0x66（按 alpha=0x80/255 与目标底色线性混合）|

- 若读回值与期望差一个固定比例（如 0.5 次幂），说明**做了不该做的 sRGB 转换**；
- 若 R/B 互换，说明通道顺序错——这正是界面颜色历史上出过的那类问题。

判据：不透明色必须**逐位相等**；半透明色允许 ±1 的取整误差。

## 4. 实现要点（工作量评估）

1. `OffscreenRenderer` 增加界面管线（顶点格式与 `UiGeometry` 一致、字体图集绑定组、alpha 混合开启）；
2. `FrameRequest` 增加可选界面几何来源（`Func<UiFrame, UiGeometry?>?`），与窗口参数同名同义；
3. 渲染顺序：地形 pass → 界面 pass（同一 render pass 内换管线，或第二个 pass）；
4. 回读：现有 PNG 输出已在回读纹理，逐像素断言可直接读取同一份像素缓冲。

预计 150–250 行 + 一处测试；风险集中在管线状态（混合、裁剪）与绑定的图集是否与窗口一致。

## 5. 非目标

- 不追求与窗口路径的**性能**一致（离屏只跑一帧）；
- 不引入第二套界面几何构造逻辑——复用 `UiGeometry`。
