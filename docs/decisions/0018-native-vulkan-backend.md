# ADR-0018 自实现原生 Vulkan 后端（**提议，未裁决**）

日期：2026-10-30　状态：**提议**（需项目所有者裁决）　影响：原则 6、渲染管线、发布形态

## 1. 与宪章的冲突（必须先声明）

`AGENTS.md` 原则 6 写明：

> MUST 通过 **WGPU** 做图形后端……不得把 OpenGL、DirectX、Vulkan、Metal 直接调用散布进业务代码。

新增原生 Vulkan 后端**不是"散布调用"**（仍收敛在抽象层内），但确实**不再"通过 WGPU"**。
⇒ 这属于**宪章变更**，按 §4.0 必须由所有者**书面授权**，我不能自行修改 `AGENTS.md`，也不能先做后报。

## 2. 决策要解决的收益

| 能力 | WGPU 现状 | Vulkan 原生 |
| --- | --- | --- |
| 几何 / 细分着色器 | **无该阶段** | 有 |
| Mesh Shader | 无 | `VK_EXT_mesh_shader` |
| 硬件光追管线（BLAS/TLAS/RT pipeline） | 仅实验性 ray query | `VK_KHR_ray_tracing_pipeline` |
| 厂商放缩（DLSS/XeSS） | 无设备互操作 | 可接（仍需各自 SDK）|
| 可变速率着色 / 稀疏资源 / bindless（descriptor indexing） | 无/受限 | 有 |
| 多队列 / 时间线信号量 | 受限 | 完整 |

## 3. 成本（必须诚实）

| 项 | 估算 |
| --- | --- |
| 后端实现 | instance/device/swapchain、内存分配器、描述符管理、管线缓存、同步/屏障、时间线 —— **万行级代码**，独立于游戏逻辑 |
| 平台覆盖变化 | **macOS 失去原生路径**（Vulkan 仅经 MoltenVK），与原则 6"三平台原生一致"直接矛盾；Windows/Linux 才有收益 |
| 维护 | 两套后端并行（WGPU 仍要保留给 macOS / 回退），回归测试面翻倍 |
| 着色器 | 可保留 WGSL 前端（`naga` 转 SPIR-V），**不必重写着色器**——这是最关键的省钱点 |
| 时间 | 以当前进度，保守 **2–4 个月**专职，且期间 P1/P2 渲染工作基本停滞 |

## 4. 证据门槛（建议在决定前先取得）

- 我们已实测：Complementary 三个样本 `.gsh`/`.tes` 计数 **0**，`.csh` 各 3；观感由阴影图/SSAO/体积光/SSR/TAA 构成，**均可在 WGPU 的 compute 内实现**。
- ⇒ 目前**没有任何目标包**证明"必须 Vulkan"；唯一确定需要原生的是 **DLSS/XeSS**，而它们与跨平台原则冲突。
- 门槛建议：在 P3（着色器包接入）落地后统计**真实目标包**对 geo/tess/RT 的依赖比例；若 ≥30% 的重要包依赖这些能力，再启动 Vulkan 后端。

## 5. 选项

| 选项 | 说明 | 代价 | 建议 |
| --- | --- | --- | --- |
| A（基线） | 只用 WGPU + compute 实现现代效果 | 低 | **当前建议** |
| B | WGPU + 已在 wgpu 暴露的扩展（实验 ray query 等，特性开关）| 中低 | 可与 A 并行 |
| C | 保留 WGPU 默认，新增**可选 Vulkan 后端**（Win/Linux）| 高（2–4 月 + 双份维护）| **需先过证据门槛 + 宪章授权** |
| D | 上上游：向 wgpu 提交所需特性 | 不可控 | 长期可考虑 |

## 6. 若批准 C 的前置条件

1. 所有者书面授权修改原则 6（改为"以 WGPU 为默认后端，允许在抽象层内提供可选原生后端"）；
2. 冻结一条"后端接口"（描述符/管线/屏障抽象），WGPU 与 Vulkan 都实现它；
3. 明确 macOS 的形态（MoltenVK 还是仅 WGPU）；
4. 明确验收：以"能加载并使用目标着色器包"为证据，不以"后端跑通"为证据。

## 7. 我的建议

**暂不启动**。理由：①当前无证据表明目标包需要；②与原则 6 与三平台一致冲突；③窗口期内它会让 P1/P2 停滞。
先做**选项 A + B**，在 P3 结束后用实测数据复核本 ADR（触发条件写进 `docs/risks.md` R-022）。
