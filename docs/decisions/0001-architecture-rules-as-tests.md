# 0001：架构规则以测试门禁落地，而非文档约定

- 状态：已采纳
- 日期：2026-10-28
- 决策者：项目所有者 + 代理
- 关联：`docs/architecture/boundaries.md` R1–R6；`docs/traceability.md` T-001/T-004；风险 R-009

## 背景

架构规则写在文档里只能靠人工评审执行。本项目由跨会话的多个代理协作，人工评审不可靠：一次漏看就会引入 Client↔Server 反向依赖，而这类错误在后期修复成本极高。

## 决策

1. 边界规则（B1–B3）以 `tests/MinecraftCSharp.Architecture.Tests` 中的测试执行，**构建即失败**。
2. 检查同时覆盖两个来源：**IL 引用**（真实耦合）与 **csproj 声明引用**（意图）。只查其一都不够——实测发现仅声明引用、尚无代码使用时，IL 里根本没有该引用，单靠反射会静默放过越界。
3. 文档一致性同样自动化：SPDX 头、索引完整性、禁止绝对路径、STATE 存在，全部由测试断言，失败等同构建失败。
4. 新增架构规则时，规则与被否原因写进 `boundaries.md`，检查写进测试，二者在同一次提交内落地。

## 影响面

- 代码：新增工程必须满足依赖方向，否则无法通过构建。
- 测试：`AssemblyBoundaryTests`、`DocumentationDriftTests` 成为门禁，不允许跳过。
- 文档：`docs/traceability.md` 必须为每条门禁登记测试路径。
- 兼容性：无运行时影响。

## 替代方案与被否原因

| 方案 | 否决原因 |
| --- | --- |
| 仅靠 Code Review 检查依赖方向 | 跨会话代理协作下不可靠，且无法防止回归 |
| Roslyn 分析器替代测试 | 编辑期反馈更好，但需要额外工程投入；先以测试起步，稳定后再评估升级 |
| 只查 csproj 声明引用 | 漏掉运行期真实耦合（例如通过反射或共享程序集引入） |
| 只查 IL 引用 | 漏掉"声明了但尚未使用"的越界意图（实测已验证会静默通过） |

## 复查条件

- 工程数量超过 15 个，或测试运行时间明显影响开发节奏时，评估迁移到 Roslyn 分析器。
- 引入跨程序集运行期插件加载（模组）时，需补充运行期依赖检查手段。
