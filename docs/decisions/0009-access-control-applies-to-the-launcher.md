# 0009：访问控制只约束启动器

- 状态：已接受
- 日期：2026-10-29
- 决策者：项目所有者（明确授权修改 AGENTS.md 7.1）+ 代理
- 关联：`AGENTS.md` 原则 7.1、原则 8；ADR-0006；`docs/modules/accounts.md`

## 背景

合规审计发现宪章内部存在冲突：

- 原则 7.1 原文禁止"未登录正版账号即可启动游戏"的**任何**路径，其中列举了"命令行直连客户端"；
- 而 ADR-0006（所有者 2026-10-28 决策）记录的设计是：闸门判定只发生在启动器，客户端收到 `--offlineDeveloperMode`
  就关闭在线服务、不做合法性判定——与原版 `Minecraft` 的行为一致。

两者字面冲突。按 4.0，代理不能自行择一，于是上报裁决。

## 决策

1. **7.1 的适用对象是启动器**（原则 8 定义的唯一门户），不是游戏客户端本体。闸门的唯一判定点是启动器的账号列表。
2. **客户端按原版语义被如实告知**：接受 `--offlineDeveloperMode` 并关闭在线服务，**不判定、不二次拦截**离线合法性。
   理由是与 Minecraft 原版行为对齐——原版游戏侧没有更严格的鉴权，本项目不擅自加严，也不擅自放宽。
3. **不把"第三方启动器可绕过闸门"登记为风险**。所有者判断：这不是本项目的缺陷，而是与原版一致的行为；
   把它写成风险等于把"未擅自发明限制"当成隐患，会误导后续评审。
4. 启动器侧的禁令保持不变且加强表述：不得存在首次使用、无网络首次运行、开发者模式、隐藏参数、内部快捷命令等任何绕过路径。

## 影响面

- 宪章：`AGENTS.md` 7.1 增加适用范围说明，并把"命令行直连客户端"一条改写为"启动器不得提供绕过路径"+
  "客户端不得自行判定"两条（所有者授权）。
- 代码：无需改动。现有实现（ADR-0006）已是该语义，本轮是把宪章对齐到实现与所有者意图。
- 测试：`AccountsTests` 继续守护启动器闸门真值表；客户端侧不新增拦截逻辑，因此不新增测试。

## 替代方案与被否原因

- **改客户端**（要求启动器签发的 HMAC 本地会话凭据）：与原则 8"换掉启动器客户端仍能跑"直接冲突，否决。
- **保留冲突并登记风险**：所有者明确否决——目标是与原版行为对齐，不擅自加严。
