# ADR-0016：资源包文件变更热加载（原版没有的扩展，默认关闭）

- 状态：**提议（待评审）**
- 日期：2026-10-30
- 相关：ADR-0015（资源包栈与重载）、原则 9（受控偏差）、原则 2（热加载与可回收）

## 背景

包作者改一个贴图就要重启客户端。原版没有该能力（只在切换资源包或 `/reload` 时整体重载）。
我们希望：**已加载的目录包里的文件变化后，实时生效**。这是**额外功能**，不得改变默认行为。

## 决策（提议）

### 1. 默认关闭 + 开关（本 ADR 明确预留）

| 入口 | 名称 | 说明 |
| --- | --- | --- |
| 环境变量 | `MC_RESOURCE_PACK_WATCH=1` | 脚本/开发常用；与现有 `MC_*` 诊断变量一致 |
| 命令行 | `--watch-resource-packs` | 启动器将来可暴露为"包作者模式"复选项 |

未开启时：**行为与原版一致**，不监听任何文件、不产生额外线程。

### 2. 监听范围

| 包类型 | 监听方式 |
| --- | --- |
| 目录包 | `FileSystemWatcher`，`IncludeSubdirectories`；`Changed/Created/Deleted/Renamed` 均计 |
| zip 包 | 只监听**该文件本身**，变化即整包重载 |
| 内置/服务器包 | 不监听 |

### 3. 去抖与合并

单次变更在 **300 ms** 静默窗口后触发一次重载；窗口内多次变更合并。编辑器"写临时文件再改名"因此只触发一次。
重载进行中再有变更：只保留"一个待办"，结束后立即补做一次，不排队堆积。

### 4. 重载方式：全快照重建 + 原子替换

复用 ADR-0015 的两阶段重载：后台建新快照（包清单/索引/元数据），主线程帧边界一次性替换。
**不做**单资源增量替换（成本高、收益低，待实测需要再议）。

### 5. 失败处理（关键）

- 文件正在写入 → 解析失败：**保留旧快照**、记诊断、不崩溃；
- 连续失败不重试风暴：只在**新的文件变更**到来时才再次尝试；
- 若包在编辑中变得非法（`pack.mcmeta` 损坏）：旧快照继续服务，界面可用。

### 6. 资源与回收

- 纹理/图集/字形/贴图按**内容哈希**做键，未变化者不重新上传 GPU；
- 旧快照在替换后不得被强引用；纹理句柄延迟一帧销毁（避免 GPU 仍在用）；
- 监听线程只做"投递变更信号"，不做解析。

### 7. 前置依赖

必须先有 ADR-0015 的包栈与**重载监听器注册表**；现有"一次性加载"点（字体图集、`GuiSpriteAtlas`、语言表、UI 文档）
需改成可重入的监听器，且顺序固定：语言/字体 → 贴图集 → UI 文档。

## 受控偏差

默认关闭时**零偏差**；开启后属**主动扩展**，登记为 `docs/specs/deviations.md` 的 D-001。

## 验收（实现时）

1. 开启后改一张贴图 → 下一帧生效，无需重启
2. 写坏 `pack.mcmeta` → 旧快照继续可用，日志有诊断
3. 连续快速保存 → 只触发一次重载（去抖）
4. zip 包被替换 → 整包重载
5. 关闭时：不创建监听线程、默认行为与原版一致（用线程数与行为断言）

## 回退

开关关闭即回到 ADR-0015 的静态栈；监听器与重载路径本身不依赖本 ADR。
