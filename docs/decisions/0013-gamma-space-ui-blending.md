# ADR-0013：界面混合在 gamma 空间进行（交换链改为非 sRGB）

- 状态：已采纳（用户 2026-10-30 明确选择方案 A）
- 日期：2026-10-30
- 相关：原则 9（行为对齐优先）、原则 6（渲染后端隔离）

## 背景

我们的交换链使用 `BGRA8UnormSrgb`，因此 GPU 在**线性空间**做混合；原版 Minecraft 没有 sRGB 帧缓冲，混合发生在 **gamma 空间**。

不透明颜色可以靠写入前 sRGB→线性预补偿（`UiGeometry.ToLinear`）对齐，之前像素验证也确实一致。但**半透明**无法这样对齐：线性空间下 `dst×(1−a)` 的结果再编码回 sRGB，与 gamma 空间直接相乘不是同一个值。

实测（50% 黑压在 164 灰上）：

| 空间 | 期望像素 |
| --- | --- |
| gamma（原版） | 82 |
| 线性（我们） | 120 |
| 我们实测 | **119** |

⇒ 我们的实现是正确的线性渲染，但与原版**渲染空间不同**，导致所有半透明元素系统性偏浅：输入框底色、聊天框底色、提示框、滚动条、行淡出。

## 决策

交换链改用 **`Bgra8Unorm`**（非 sRGB），并取消 `ToLinear` 预补偿，使混合在 gamma 空间进行，与原版一致。

## 影响与验证

- 界面：所有半透明元素的合成结果与"gamma 空间公式"一致；不透明元素维持原值。
- 世界与实体渲染：原先写入线性值到 sRGB 目标、由硬件编码；改为非 sRGB 目标后必须由着色器自行编码，否则世界会整体偏暗。此项必须逐像素核对（草地/石头/天空各取一点）。
- 文字：字形贴图是 sRGB，采样后为线性，写入非 sRGB 目标前同样需要编码。

## 备选（未采纳）

保留 sRGB 交换链，按"线性结果≈gamma 目标"反解 alpha：只能在特定底色上近似，多种底色下仍然偏差，且要逐元素调参。

## 回退

改动集中在交换链格式与 `UiGeometry.AppendQuad` 的一行；若世界像素核对不通过，回退这两处即可恢复。
