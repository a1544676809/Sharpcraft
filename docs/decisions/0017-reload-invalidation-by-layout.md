# ADR-0017：热加载的失效策略——按布局差异分层，而非一律全量作废

- 状态：**已接受**（所有者 2026-10-30 确认：允许略微卡顿，采用分层失效）
- 相关：ADR-0016（文件变更热加载）、原则 9（行为对齐 + 更优实现）

## 背景

原版重载成功后直接 `levelExtractor.allChanged()`（全部区块几何重建，`Minecraft.reloadResourcePacks` 成功分支）。
那是**用户主动触发、有加载界面**的场景。我们的热加载由文件监听触发，作者可能每秒保存多次，
照搬"每次全量重建"会明显卡顿。

但"分辨率变化"并不等于"必须全量重建"：真正决定几何是否失效的是**图集布局**（图集尺寸与每个精灵的矩形）。

## 决策

按**布局差异**分层：

| 层 | 判据 | 动作 | 代价 |
| --- | --- | --- | --- |
| ① 布局不变 | 重建后图集尺寸与每个精灵 `(x,y,w,h)` 全部相同 | 只重传纹理（可只重传变化的子矩形），**几何不动** | 一次上传 |
| ② 布局改变 | 任一处不同（典型：16x→32x） | **全量重建几何**（等同原版 `allChanged`）| 允许卡一次 |
| ③ 后续（登记不做） | — | 几何存"精灵 id + 局部 UV"，绘制期解析 ⇒ 布局变化也无需重建 | 架构改动大 |

判据来自**比较**，不靠猜：重建候选图集后逐 rect 比对。

## 影响

- `WindowedRenderer` 需要能换图集纹理与其绑定组（地形 1 套 + UI 1 套，共 2 处），旧资源延后一帧释放。
- `WindowCommand` 的重载监听器：重建图集 → 比较布局 → ①只提版本换纹理 / ②先作废全部区块几何再提版本。
- 可观测像素与原版一致；差别只在"何时重建几何"，而对齐标准是像素与正确性（原则 9）。

## 备选（未采纳）

- 一律全量重建：简单但每次保存都卡，违背热加载初衷。
- 一律不重建：布局一变就出现错位面，正确性错误。

## 回退

若分层判据出错（例如漏比某字段），退化为层 ② 的全量重建即可保证正确性；这也是唯一的兜底路径。
