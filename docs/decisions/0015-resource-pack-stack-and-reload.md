# ADR-0015：资源包栈与运行时重载

- 状态：**提议（待评审）**
- 日期：2026-10-30
- 相关：原则 2（模组热加载）、原则 3（资产不入库）、原则 9（行为对齐）

## 背景

提示框贴图目前只从"基础包 zip"读取。原版是**多包栈**：按包列表顺序建立每命名空间的回退栈，**列表靠后者覆盖靠前者**，
并支持运行时重载（两阶段：准备 → 应用）。第三方资源包（目录或 zip）必须能进入这个栈并生效与可撤销。

## 决策（提议）

1. **包模型**：`PackSource`（内置 / 目录 / zip / 服务器下发）+ `PackEntry`（id、来源、`pack.mcmeta` 元数据、`filter` 段）。
2. **栈语义**：与 `MultiPackResourceManager` 一致——按列表顺序压栈、查找从栈顶（列表末尾）向前；`filter` 包只遮蔽不提供。
3. **重载**：两阶段（准备期构建新的只读快照，应用期在帧边界一次性替换引用）；失败则保留旧快照，不半应用。
4. **可回收**：旧快照被替换后不得有强引用残留（与原则 2 的 ALC 要求一致），需要自动化验证手段。
5. **发现顺序**：先按 §5 补齐"客户端包来源顺序"的核对，再冻结实现；顺序未定前不写代码。

## 影响

- `AssetStack`/`ZipAssetSource` 演进为通用包栈；`PrepareFont`/`PrepareGuiSprites` 改为从栈中按优先级读取。
- 需要处理包格式兼容（`pack.mcmeta` 的支持区间）与缺 `pack` 段的回退。
- 与本项目的模组资源注入共用一套替换机制。

## 备选（未采纳）

按文件逐个"最后修改覆盖"：无法表达 `filter` 与包顺序，也无法原子回滚。

## 回退

新栈以只读快照形式存在；旧路径（单包）保留为只有一个元素的栈，切换是配置而非重写。
