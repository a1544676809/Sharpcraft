# ADR-0015：图集 UV 覆盖完整精灵，改用 padding 防渗色

- 状态：已接受（2026-10-31，由项目所有者确认方向后实施）
- 相关：原则 12（规格变更审批）、Repro-003、`SpriteAtlas`

## 背景

方块贴图来自一张拼接图集。早期为了对抗"最近邻采样落在格子边界取到隔壁精灵"的渗色，把每个精灵的 UV 在四个方向各**向内缩半个纹素**。
这确实避开了边界取样，但同时把 16 像素的贴图摊到 **15 个纹素**上：最外一圈纹素永远采不到，方块交界处的插值落在最后一列纹素的暗边上。
表现就是**每个方块四周有细黑线**，远处叠加成整面发黑（真实服务器截图上可见）。

## 决定

1. 精灵 UV **覆盖完整精灵**：`U0 = x / size`、`U1 = (x + width) / size`（V 同理）。
2. 渗色改由 **拼接期 padding** 解决：每个精灵四周留 1 纹素，用自身边缘像素复制填充；mip 各级同样把边缘复制进 padding 环。
3. 采样保持**连续 UV + 硬件 LOD**（不做逐纹素吸附、不手算 LOD）。

## 影响

- 纹理按纹素 1:1 显示，方块边缘的细黑线消失。
- `Repro-003` 的前提（靠缩进防渗色）已不成立，用例改写为钉住新约定：UV 恰好覆盖精灵 + padding 环复制边缘本身。
- `SpriteAtlasTests.TextureCoordinatesCoverTheSpriteExactly` 同步更新期望值。
- 图集尺寸略增（每个精灵多 2 像素边），布局仍是确定性的。

## 备选与为何未采用

- **逐纹素吸附 + 禁用 mip**：边缘干净但远处严重摩尔纹（已实测）。
- **手算 LOD（`textureSampleLevel`）**：实测出现抖动/破碎，且与 fract 坐标的导数不连续。
- **显式梯度（`textureSampleGrad`）**：当前环境下窗口无响应，未采用。
