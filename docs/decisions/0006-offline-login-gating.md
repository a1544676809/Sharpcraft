# ADR-0006：离线登录的闸门、身份派生与防篡改边界

## 背景

原则 7.1 早已规定：启动器必须原生支持多账号；**只有存在至少一个已通过官方认证的正版账号时**才允许离线登录；正版账号全部删除后离线能力必须立即失效；不得留任何后门。项目所有者 2026-10-28 确认"我们已经登录了正版账号，因此我们可以允许用离线账号登录了"，即授权实现该策略。

问题不在于"要不要做"，而在于三处容易做错的实现选择：闸门怎么评估、离线身份怎么派生、防篡改做到哪一步为止。

## 决策

1. **闸门是实时函数，不是状态位**
   `OfflineLoginGate.Evaluate(accounts)` 每次按当前列表计算 `Available`。禁止缓存布尔值、禁止写"已解锁"标记文件。理由：原则 7.1 要求删除后"立即"失效，缓存是唯一能让它变成"下次启动才失效"的实现方式。

2. **离线身份按原版规则派生**
   `uuid = nameUUIDFromBytes("OfflinePlayer:" + name, UTF-8)`（MD5/v3）。证据：`ref://mc-26.3-analysis/src/net/minecraft/core/UUIDUtil.java`、`.../client/main/Main.java`（无 `--uuid` 参数时的默认路径）。理由：UUID 必须与原版客户端在同一名字下一致，否则服务器上的玩家数据、白名单、OP 名单都对不上。

3. **离线启动不给客户端任何令牌，形态照原版**
   启动器传 `--offlineDeveloperMode --username <name> --uuid <派生值>`，不传 `--accessToken`，也不传会话文件。理由：原版客户端正是这样工作的（`Main` 的 `--offlineDeveloperMode` 开关 + `Minecraft` 里 `offlineDeveloperMode ? UserApiService.OFFLINE : …`），而且"没有令牌"比"伪造令牌"更难被误用——没有任何代码路径可以把离线会话当成在线凭据。

4. **防篡改做到"本地策略"为止**
   `accounts.json` 用 HMAC-SHA256 保护，密钥放平台安全存储（Windows DPAPI，其它平台受限权限文件）。校验失败 → 视为空列表并要求重新登录正版账号，不做修复尝试。明确不承诺抵抗有内核权限的攻击者（原则 7.1 的原文即"本地策略，非 DRM 承诺"）。

5. **客户端不判断离线是否合法**
   判定只发生在启动器（原则 7.1 是启动器职责）。客户端收到 `--offlineDeveloperMode` 就关闭在线服务，不重复、也无法重复判定——原版同样是"被告知"，不是"自己判断"。这样第三方启动器只要按原版形态传参就能用我们客户端。

6. **不提供任何绕过入口**
   不加跳过开关、不加隐藏参数、不加"仅测试"分支。自动化测试使用夹具账号（纯内存构造），不接触真实账号。

## 已裁决（2026-10-28，所有者确认）

1. **离线账号保留、但无正版账号时不能启动游戏**：删掉最后一个正版账号后，已有离线账号仍在列表里，但任何启动尝试都拒绝，必须先登录一个正版账号。不采用"直接删除离线账号"。
2. **启动形态照原版**：用 `--offlineDeveloperMode` + `--username`（`--uuid` 由启动器显式给出），不传令牌。
3. **客户端不做合法性判定**：与原版一致。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **实时闸门 + HMAC 账号文件**（采纳） | 语义与原则 7.1 一致；不引入状态位 | 每次启动要校验 HMAC（可忽略） | 采纳 |
| 一次性"解锁标记"文件 | 实现最简单 | 删除全部正版账号后仍可离线，直接违反 7.1 | 否决 |
| 离线启动传固定哨兵令牌 | 命令行形态统一 | 原版不这么做；哨兵一旦被在线路径误用就是安全隐患 | 否决，改为完全不传令牌 |
| 离线身份用随机 UUID | 免去派生规则 | 与原版不一致，服务器视为新玩家，数据丢失 | 否决 |
| 离线身份用名字的 SHA-1 | 免去 MD5 | 与原版不一致 | 否决 |
| 不做防篡改 | 少写代码 | 用户手工编辑账号文件即可绕过闸门 | 否决（SHOULD 项，成本很低） |

## 后果

- **正面**：离线能力与"是否拥有正版账号"严格绑定；身份与原版兼容；篡改账号文件会直接失去离线能力（而不是悄悄放行）。
- **负面**：用户删掉全部正版账号后无法再离线玩（这是策略要求，不是缺陷）；HMAC 密钥丢失等于要重新登录一次正版。
- **影响其它文档**：`docs/modules/launcher.md` 命令表新增 `accounts` 系列与 `launch --offline`；`docs/traceability.md` 新增对应任务行；`docs/STATE.md` 记录授权来源。

## 复查条件

- 若将来做图形启动器，"离线入口隐藏/禁用"由 UI 层实现，闸门本身不变。
- 若平台安全存储方案变更（例如改用系统密钥链），只替换密钥提供者，不影响闸门与派生规则。
